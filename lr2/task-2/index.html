Задача 2. Параллельный парсинг веб-страниц

Постановка задачи

Нужно написать три программы для параллельного парсинга нескольких веб-страниц с сохранением результата в базу данных:

  • через threading;
  • через multiprocessing;
  • через asyncio и aiohttp.

Каждая программа должна содержать функцию parse_and_save(url), которая загружает HTML-страницу, извлекает заголовок страницы, сохраняет данные в базу данных и выводит результат на экран.

Связь с базой данных ЛР 1

В лабораторной работе 1 была реализована база данных тайм-менеджера. Основная таблица этой предметной области — Task.

Во второй задаче парсер загружает страницы официальной документации Python и сохраняет их как учебные задачи:

Поле таблицы Task Значение
title Изучить материал: <заголовок страницы>
description Учебный источник: <URL>
priority medium
status planned
category_id категория Учебные материалы Python

Таким образом, парсер не сохраняет случайные данные, а автоматически формирует список задач на изучение материалов Python.

В качестве источников используются страницы документации Python:

Общий модуль parser_common.py

Общая логика вынесена в файл lr_2/task_2/parser_common.py, чтобы не дублировать один и тот же код в трех программах.

В этом модуле находятся:

Элемент Назначение
URLS список страниц для парсинга
split_urls() разбиение списка URL на части
fetch_html() синхронная загрузка HTML для threading и multiprocessing
TitleParser HTML-парсер для извлечения содержимого тега <title>
extract_title() функция извлечения заголовка страницы
save_title_to_db() сохранение или обновление задачи в базе данных
parse_and_save_sync() полный синхронный цикл обработки одного URL

Для повторного запуска используется обновление существующих записей. Если задача с таким description уже есть в базе, программа обновляет ее, а не создает дубль.

Threading

Файл lr_2/task_2/threading_parser.py использует модуль threading.

Список URL делится на части:

url_chunks = split_urls(URLS, PARSER_WORKERS_COUNT)

Для каждой части создается поток:

thread = threading.Thread(target=worker, args=(chunk, results))
thread.start()

Каждый поток выполняет worker, который последовательно вызывает parse_and_save(url) для своей части URL.

Особенность подхода: потоки хорошо подходят для сетевого парсинга, потому что пока один поток ждет ответ сайта, другие потоки могут продолжать работу.

Multiprocessing

Файл lr_2/task_2/multiprocessing_parser.py использует multiprocessing.Pool.

Основной фрагмент:

with multiprocessing.Pool(processes=PARSER_WORKERS_COUNT) as pool:
    chunk_results = pool.map(worker, url_chunks)

Каждый процесс получает свою часть URL и возвращает список результатов.

Особенность подхода: процессы имеют отдельную память, поэтому программа не использует общий список результатов. Вместо этого каждый процесс возвращает данные родительскому процессу через pool.map.

Для парсинга веб-страниц multiprocessing обычно менее выгоден, чем threading или asyncio, потому что задача в основном ожидает сеть, а создание процессов добавляет накладные расходы.

Async

Файл lr_2/task_2/async_parser.py использует asyncio и aiohttp.

HTML загружается асинхронно:

async with session.get(url) as response:
    response.raise_for_status()
    return await response.text()

Асинхронные работники создаются через:

tasks = [
    asyncio.create_task(worker(session, chunk))
    for chunk in url_chunks
]
chunk_results = await asyncio.gather(*tasks)

Так как SQLModel работает синхронно, сохранение в базу данных запускается через:

task_id, action = await asyncio.to_thread(save_title_to_db, url, title)

Это позволяет не блокировать event loop во время записи в базу.

Результаты запуска

Фактические результаты запуска:

Подход Количество работников Успешно обработано страниц Время выполнения
threading 3 потока 6/6 1.665542 секунд
multiprocessing 3 процесса 6/6 2.305063 секунд
async/await 3 асинхронные задачи 6/6 0.819932 секунд

Анализ результатов

Все три подхода успешно обработали 6 страниц из 6 и сохранили данные в базу.

Первый запуск создал записи в таблице Task, поэтому вывод содержал created. Следующие запуски обновили те же записи, поэтому вывод содержал updated. Это корректное поведение, потому что программа ищет существующую задачу по URL в поле description и не создает дубликаты.

Лучшее время показал async/await — 0.819932 секунд. Это ожидаемо, потому что парсинг веб-страниц относится к I/O-bound задачам. Основное время программа ожидает ответы сайтов и операции ввода-вывода, а asyncio эффективно переключается между задачами в точках await.

threading также хорошо подходит для сетевых задач, но имеет больше накладных расходов, чем асинхронные задачи. В данном запуске он занял 1.665542 секунд.

multiprocessing оказался самым медленным — 2.305063 секунд. Для сетевого парсинга процессы обычно избыточны: создание процессов, передача данных и сбор результатов добавляют расходы, а преимущества выполнения на разных ядрах почти не используются.

Вывод по задаче 2

Для параллельного парсинга веб-страниц наиболее эффективным оказался асинхронный подход с asyncio и aiohttp. threading также подходит для I/O-bound задач, но уступил по времени. multiprocessing лучше применять для CPU-bound вычислений, а не для задач, где основное время занимает ожидание сети.
