# Задача 1. Сравнение threading, multiprocessing и async

## Постановка задачи

Нужно написать три программы на Python, использующие разные подходы к параллельному выполнению:

- `threading`;
- `multiprocessing`;
- `asyncio` и `async/await`.

Каждая программа должна посчитать сумму всех чисел от `1` до `10_000_000_000_000`, разбить вычисление на несколько подзадач, измерить время выполнения и вывести результат.

## Общий принцип решения

Диапазон чисел делится на несколько частей. Каждая часть считается отдельно, затем частичные суммы складываются.

Прямой цикл до `10_000_000_000_000` занял бы слишком много времени, поэтому сумма каждого диапазона считается по формуле арифметической прогрессии:

```python
(start + end) * (end - start + 1) // 2
```

Эта формула позволяет быстро получить сумму диапазона от `start` до `end` включительно.

## Реализованные программы

| Файл | Подход | Описание |
|---|---|---|
| `lr_2/task_1/threading_sum.py` | `threading` | Создает несколько потоков, каждый поток считает сумму своего диапазона |
| `lr_2/task_1/multiprocessing_sum.py` | `multiprocessing` | Создает пул процессов и распределяет диапазоны между ними |
| `lr_2/task_1/async_sum.py` | `asyncio` | Создает несколько асинхронных задач и ожидает их через `asyncio.gather` |
| `lr_2/task_1/run_all.py` | общий запуск | Последовательно запускает все три программы |

## Threading

В файле `threading_sum.py` используется модуль `threading`.

Главная идея:

```python
thread = threading.Thread(
    target=worker,
    args=(index, range_start, range_end, results),
)
thread.start()
```

Каждый поток вызывает функцию `worker`, которая считает сумму своего диапазона через `calculate_sum()` и записывает результат в общий список `results`.

После запуска всех потоков основной поток вызывает:

```python
thread.join()
```

Метод `join()` нужен, чтобы дождаться завершения всех потоков перед подсчетом итоговой суммы.

Особенность подхода: потоки имеют общую память, но в CPython ограничены GIL. Поэтому для CPU-bound задач `threading` обычно не дает полноценного ускорения на нескольких ядрах.

## Multiprocessing

В файле `multiprocessing_sum.py` используется модуль `multiprocessing`.

Главная идея:

```python
with multiprocessing.Pool(processes=WORKERS_COUNT) as pool:
    partial_sums = pool.starmap(calculate_sum, ranges)
```

`Pool` создает несколько процессов. Метод `starmap` передает каждому процессу пару аргументов `(start, end)`.

Особенность подхода: каждый процесс имеет собственную память и собственный интерпретатор Python. Это позволяет обходить ограничение GIL и использовать несколько ядер процессора. Но запуск процессов имеет заметные накладные расходы.

## Async

В файле `async_sum.py` используется `asyncio`.

Главная идея:

```python
tasks = [
    asyncio.create_task(calculate_sum(range_start, range_end))
    for range_start, range_end in ranges
]
partial_sums = await asyncio.gather(*tasks)
```

Создается несколько асинхронных задач, которые ожидаются через `asyncio.gather`.

Особенность подхода: `asyncio` не создает несколько процессов и не выполняет CPU-код на нескольких ядрах. Он полезен прежде всего для I/O-bound задач, где программа много ждет.

Фактические результаты запуска:

## Анализ результатов

Все три программы получили одинаковую сумму и прошли проверку результата.

Быстрее всего в данном запуске отработал `async/await`, затем `threading`, затем `multiprocessing`. Такой результат объясняется тем, что вычисление выполняется по формуле и занимает очень мало времени. Поэтому на первый план выходят накладные расходы:

- `asyncio` создает легковесные задачи внутри одного event loop;
- `threading` создает потоки внутри одного процесса;
- `multiprocessing` создает отдельные процессы, что заметно дороже.

Важно, что этот результат не означает, что `asyncio` лучше подходит для тяжелых вычислений. Для реальных CPU-bound задач предпочтительнее `multiprocessing`, потому что процессы могут выполняться на разных ядрах и не ограничиваются одним общим GIL. `asyncio` лучше использовать для задач, связанных с ожиданием сети, файлов или базы данных.

## Вывод по задаче 1

Задача показала различие между тремя моделями выполнения. `threading` и `asyncio` имеют меньшие накладные расходы на коротком вычислении, а `multiprocessing` показывает большую стоимость запуска процессов. При этом для тяжелых вычислительных задач именно `multiprocessing` остается наиболее подходящим вариантом.
