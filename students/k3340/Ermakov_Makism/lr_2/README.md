# Лабораторная работа 2

## Тема

Потоки. Процессы. Асинхронность.

## Цель

Понять отличия между потоками, процессами и асинхронным выполнением в Python.

## Задача 1

Нужно посчитать сумму всех чисел от `1` до `10_000_000_000_000`, разбив вычисление на несколько параллельных подзадач.

Для первой задачи в папке `task_1` находятся три отдельные программы:

| Файл | Подход | Используемый инструмент |
|---|---|---|
| `task_1/threading_sum.py` | Потоки | `threading` |
| `task_1/multiprocessing_sum.py` | Процессы | `multiprocessing` |
| `task_1/async_sum.py` | Асинхронность | `asyncio`, `async/await` |

### Запуск задачи 1

Запуск каждой программы отдельно:

```bash
cd task_1
python threading_sum.py
python multiprocessing_sum.py
python async_sum.py
```

Запуск всех вариантов подряд:

```bash
cd task_1
python run_all.py
```

## Особенность вычисления

Прямой цикл от `1` до `10_000_000_000_000` занял бы слишком много времени, поэтому каждая подзадача считает сумму своего диапазона по формуле арифметической прогрессии:

```python
(start + end) * (end - start + 1) // 2
```

Такой способ сохраняет смысл задачи: диапазон делится на несколько частей, каждая часть считается отдельно, а затем частичные суммы объединяются.

## Сравнение подходов

- `threading` запускает несколько потоков внутри одного процесса. Для CPU-bound задач в Python потоки ограничены GIL, поэтому реального ускорения вычислений обычно не дают.
- `multiprocessing` запускает отдельные процессы. Для тяжелых CPU-bound задач это наиболее подходящий вариант, потому что каждый процесс может работать на отдельном ядре.
- `asyncio` полезен для I/O-bound задач: сетевые запросы, файлы, ожидание внешних операций. Для чистых вычислений асинхронность не ускоряет работу сама по себе, потому что задачи выполняются в одном потоке событийного цикла.

## Задача 2

Нужно параллельно загрузить несколько HTML-страниц, получить их `<title>` и сохранить результат в базу данных из лабораторной работы 1.

В ЛР 1 реализован тайм-менеджер, поэтому результат парсинга сохраняется в таблицу `Task` как список учебных задач по Python:

- `title` — задача вида `Изучить материал: <заголовок HTML-страницы>`;
- `description` — учебный источник вида `Учебный источник: <URL>`;
- `priority` — `medium`;
- `status` — `planned`.
- `category_id` — категория `Учебные материалы Python`.

Парсер загружает не случайные сайты, а страницы официальной документации Python по темам лабораторной работы: `threading`, `multiprocessing`, `asyncio`, `html.parser`, `urllib.request` и `sqlite3`.

Для повторного запуска используется простое обновление: если задача с таким URL уже есть в базе, ее заголовок обновляется, а не создается бесконечное количество дублей.

### Файлы задачи 2

| Файл | Подход | Используемый инструмент |
|---|---|---|
| `task_2/threading_parser.py` | Потоки | `threading`, `urllib.request` |
| `task_2/multiprocessing_parser.py` | Процессы | `multiprocessing`, `urllib.request` |
| `task_2/async_parser.py` | Асинхронность | `asyncio`, `aiohttp` |

### Как работает сохранение в базу

Файл `parser_common.py` подключает модели из `lr_1/lab_1`, читает строку подключения `DB_ADMIN` из `lr_1/lab_1/.env`, создает таблицы через `SQLModel.metadata.create_all(engine)`, создает категорию `Учебные материалы Python` и сохраняет заголовки страниц в существующую таблицу `Task`.

### Сравнение подходов для парсинга

- `threading` хорошо подходит для парсинга страниц, потому что сетевые запросы являются I/O-bound задачей: поток может ждать ответ сайта, пока другие потоки продолжают работу.
- `multiprocessing` тоже выполняет работу параллельно, но для сетевого парсинга обычно избыточен: процессы тяжелее потоков, а основное время все равно уходит на ожидание сети.
- `asyncio` и `aiohttp` хорошо подходят для большого количества сетевых запросов, потому что один поток может обслуживать много задач и переключаться между ними в точках `await`.
